# 文档校验工作台 UI 调整设计

## 目标

在不改变 DOCX 检测、报告数据结构和术语 API 的前提下，收敛页面层级、补齐说明入口、改善阈值可理解性、优化句子级术语添加交互，并让报告页具备更清晰的工作台结构和下载入口。

## 设计决定

### 页面与标题

- 将首页、报告页、历史页和术语页的主标题统一收小，桌面端最大约 4rem，移动端使用更紧凑的 `clamp`。
- 报告页标题区增加“返回首页”动作，保留已有报告 HTML 下载，并新增 JSON 下载。
- 首页顶部导航新增“使用说明”，指向 `/guide`；说明页以四个短步骤说明上传、阈值、报告和术语操作。

### 阈值提示

检测阈值和纠正阈值旁各放一个可键盘聚焦的提示按钮。提示使用原生可访问语义和轻量浮层，不改变阈值状态或任务请求：

- 检测阈值越低，召回更多疑似问题，但误报可能增多。
- 纠正阈值越低，采纳更多模型建议；越高，结果更保守。
- 推荐先降低检测阈值观察召回，再提高纠正阈值控制误报。

### 句子级术语操作

- 只有 `TEXT_CORRECTION` 问题显示“添加为术语”按钮。
- 每条问题卡片视为一个句子上下文；用户划选上下文中的文字后，按钮进入蓝色可点击状态。
- 未选择文字时按钮禁用并显示提示；选择后复用现有术语库弹窗和重新匹配流程。
- 标点、版式、结构和引用问题不显示术语按钮。

### 报告页

报告页沿用现有问题清单作为主内容，增加工作台式头部、统计卡、筛选工具栏、空结果提示和更清晰的卡片层级。下载动作同时提供 HTML 和 JSON，均使用现有后端接口。

## 组件边界

- `GuidePage` 只负责说明内容和返回首页导航。
- `IssueContext` 负责上下文渲染和当前划词状态通知。
- `IssueList` 负责根据问题类别决定是否渲染句子级术语按钮。
- `ReportPage` 负责下载动作、返回动作和现有术语弹窗状态，不新增后端数据。
- `styles.css` 负责全局标题比例、报告页层级、提示浮层、按钮状态和响应式布局。

## 验收标准

- 所有主标题明显小于当前版本，桌面和移动端均不溢出。
- 报告页可以返回首页，并可下载 HTML 与 JSON。
- `/guide` 可从首页进入，说明内容覆盖四步操作。
- 两个阈值提示可通过鼠标和键盘触发，文案解释含义和调节方向。
- 文字纠错卡片支持划词后添加术语；非文字纠错卡片没有该按钮。
- 前端测试、lint、build 全部通过，现有 DOCX 上传和报告流程测试不回归。
