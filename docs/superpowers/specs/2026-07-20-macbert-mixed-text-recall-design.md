# MacBERT 混合文本召回修复设计

## 目标

修复 `pycorrector.MacBertCorrector` 在包含数字、英文或特殊符号的句子中因 token 数量无法与字符数量对齐而整句回退的问题，并在首页效果测试入口提供推理阈值调节。

修复同时作用于纯文本测试接口和现有 DOCX 模型校验路径。DOCX 上传、任务队列、规则、术语库、报告结构和历史任务行为保持不变。

## 已确认根因

当前环境使用 `pycorrector 1.1.3`。其 MacBERT 推理会比较解码 token 数与原字符串字符数；数量不一致时直接返回原句。实测完整句子“2023年学员平均就业新资18K/月（高于行业均值32%）”在 `threshold=0.9` 到 `0.0` 之间均无结果，而纯中文片段“学员平均就业新资”能稳定纠正为“学员平均就业薪资”。因此该案例的首要问题是混合文本对齐回退，不是置信度阈值。

## Corrector 设计

- `MacBertCorrector.correct_raw()` 增加 `threshold: float = 0.7` 参数，并把参数传给底层 `correct_batch()`。
- 推理前按连续中文字符区间提取模型输入；数字、拉丁字母、空白和标点作为不可修改的原文间隔保留。
- 同一批输入中的所有中文区间合并为一次底层批量调用，避免逐区间重复推理。
- 根据每个区间在原文中的起止位置，把模型返回的 `target` 和 `errors` 合并回完整原句：
  - `source` 始终为完整输入。
  - `target` 保留非中文内容，只替换对应中文区间。
  - `errors` 的局部起点转换为完整原句的全局起点。
- 没有中文字符的输入直接返回原文和空错误，不加载或调用模型。
- 对纯中文输入仍保持现有 `source / target / errors` 结构。
- `correct()` 继续调用 `correct_raw()` 并转换为项目内 `CorrectionResult`，因此 DOCX 路径自动得到相同修复。

中文区间采用基本汉字与扩展 A 范围：`[\u3400-\u4DBF\u4E00-\u9FFF]+`。该范围覆盖当前简体中文论文场景，同时避免把数字、英文和标点送入现有易失配的解码路径。

## API 与页面设计

- `POST /api/v1/macbert/test` 请求增加可选字段 `threshold`，范围为 `0.0` 到 `1.0`，默认 `0.7`。
- 非法阈值由请求模型返回 422；现有空文本和模型不可用错误保持不变。
- 首页测试区增加阈值滑杆和当前数值，步长 `0.05`、默认 `0.70`。
- 点击“测试模型”时同时发送文本和阈值，结果区继续显示合并后的 `source / target / errors` JSON。
- 阈值只影响交互测试；DOCX 校验继续使用默认 `0.7`，避免无评估依据地改变产品误报率。

## 测试与验收

- Corrector 单元测试覆盖：
  - 混合文本只把中文区间送给 backend。
  - “新资”纠正结果能合并回完整原句。
  - 错误位置从区间局部偏移转换为全文偏移。
  - `threshold` 原样传给 backend。
  - 纯非中文文本不调用 backend。
- API 测试覆盖自定义阈值透传及范围校验。
- 首页测试覆盖阈值调节、请求体和结果展示，同时继续断言 DOCX 上传入口存在。
- 后端非模型测试、前端测试、类型检查和生产构建全部通过。
- 使用本机真实模型验证完整混合句，期望得到“薪资”和对应全局错误位置。

## 风险与边界

- 中文分段会减少跨数字或英文片段的上下文，但比整句静默跳过更可控；非中文内容不会被模型误改。
- 降低阈值可能提高召回，也可能增加误报。正式 DOCX 默认阈值不在本次修改中调整。
- 已知领域错词仍可在后续增加确定性混淆词规则；本次不引入新的规则或模型。
