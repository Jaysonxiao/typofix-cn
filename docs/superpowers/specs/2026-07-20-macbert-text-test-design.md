# MacBERT 纯文本效果测试入口设计

## 目标

把首页顶部过大的宣传标题替换为一个紧凑的 MacBERT 纯文本效果测试入口。用户输入一段中文后，可直接查看 `pycorrector.MacBertCorrector` 返回的原始结果。

现有 DOCX 上传、校验模式、术语库选择、任务队列、报告生成、历史任务和术语库页面全部保留，行为不变。

## 页面设计

- 首页顶部保留现有品牌栏和导航。
- 删除“把论文里的小毛刺，留在交稿前。”及其说明文案。
- 在原位置放置紧凑的“MacBERT 效果测试”区域，包含多行纯文本输入框、“测试模型”按钮、加载状态、错误提示和结果区。
- 结果区使用格式化 JSON 原样展示模型返回的 `source`、`target`、`errors` 等字段，不转换成 DOCX 报告问题。
- 原有 DOCX 工作区继续显示在测试区域下方，组件和交互保持不变。

## 后端设计

- 在 `MacBertCorrector` 中增加原始批量推理入口。该入口继续复用现有的延迟模型加载和 `ModelDependencyMissing`、`ModelNotReady`、`ModelInferenceError` 异常边界，但不调用 `_convert()`。
- 现有 `correct()` 改为复用原始批量推理入口后再执行 `_convert()`，保证 DOCX 分析所得结构与当前行为一致。
- 新增 `POST /api/v1/macbert/test`：
  - 请求：`{"text": "待检测文本"}`。
  - 成功响应：模型对该文本返回的第一条原始 JSON 字典。
  - 空白文本返回 422。
  - 模型依赖缺失、模型未就绪或推理失败时，接口返回可展示的中文错误消息，详细异常保留在服务端。
- 测试接口使用应用级专用 `MacBertCorrector` 实例，使模型在首次请求时加载，并在后续测试请求中复用。现有 DOCX 任务创建和执行路径不改动。

## 前端调用

- API 客户端增加纯文本测试函数和原始结果类型。
- 首页为测试区维护输入、加载、结果和错误状态。
- 点击按钮后调用新接口；请求过程中禁用按钮，成功时覆盖显示最新原始结果，失败时显示中文错误。
- 文本为空时不发请求。

## 测试与验收

- `MacBertCorrector` 测试证明原始入口不转换模型字典，并且现有 `correct()` 转换结果保持不变。
- API 测试覆盖成功返回原始字典和空白文本校验。
- 首页测试覆盖输入文本、发起请求和展示原始 JSON；现有 DOCX 上传测试继续通过。
- 前端测试、类型检查和构建通过，后端相关测试通过。
- 首页顶部不再出现旧宣传标题，且 DOCX 工作区仍可正常上传并启动校验。

## 非目标

- 不修改 DOCX 校验规则、术语库、报告结构或任务状态机。
- 不把纯文本测试保存为历史任务。
- 不对模型原始结果做二次解释、筛选或格式转换。
